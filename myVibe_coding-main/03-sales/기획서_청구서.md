# 거래처별 월간 청구서 PDF 생성 프로그램 기획서

## 1. 프로그램 목적

`매출.xlsx`의 `매출` 시트에서 사용자가 지정한 연도와 월의 매출만 골라 거래처별로 묶습니다. `거래처` 시트에서 우편번호, 주소, 거래처명을 찾아 `청구서.xlsx` 양식에 넣고, 거래처마다 PDF 파일 한 개를 `PDF` 폴더에 저장합니다.

같은 연월과 거래처의 청구서를 다시 만들면 같은 이름의 PDF를 덮어씁니다. 원본인 `매출.xlsx`와 `청구서.xlsx`는 수정하지 않습니다.

## 2. 확인한 파일 구조

```text
03-sales/
├─ 매출.xlsx
├─ 청구서.xlsx
├─ 기획서_청구서.md
├─ make_invoices.py        # 다음 단계에서 작성할 프로그램
└─ PDF/
   └─ 생성된 청구서 PDF
```

### 2.1 `매출.xlsx`

- 시트: `매출`, `거래처`, `서울`, `대전`, `수원`
- 이번 프로그램이 읽는 시트: `매출`, `거래처`
- `매출` 시트 사용 범위: `A1:P151`
- 값이 있는 매출 데이터: 제목을 제외하고 75건
- 확인된 매출 기간: 2026년 10월과 11월
- 2026년 10월: 거래처 11곳, 매출 38건, 한 거래처의 최대 상세행 8건
- 2026년 11월: 거래처 11곳, 매출 37건, 한 거래처의 최대 상세행 6건
- 76행부터 151행까지는 값이 없지만 서식이 남아 있으므로 매출 데이터로 세지 않습니다.

`매출` 시트에서 사용할 열은 다음과 같습니다.

| 용도 | 열 제목 | 열 위치 |
|---|---|---:|
| 월 범위 판정 및 청구서 날짜 | 매출일 | A열 |
| 거래처 묶음 기준 | 거래처코드 | K열 |
| 대조용 거래처명 | 거래처명 | L열 |
| 청구서 상품명 | 상품명 | G열 |
| 청구서 수량 | 매출수량 | M열 |
| 대조용 매출금액 | 매출금액 | N열 |
| 청구서 단가 | 단가 | P열 |

`거래처` 시트에서 사용할 열은 다음과 같습니다.

| 용도 | 열 제목 | 열 위치 |
|---|---|---:|
| 매출과 거래처 정보 연결 | 거래처코드 | A열 |
| 청구서 거래처명 | 거래처명 | B열 |
| 청구서 우편번호 | 우편번호 | C열 |
| 청구서 주소 | 주소 | D열 |

확인 결과 거래처는 11곳이며 거래처코드 중복이 없습니다. 현재 매출의 모든 거래처코드가 `거래처` 시트에 있고, 거래처명도 일치합니다. 우편번호는 앞자리 0이 유지되어야 하므로 문자열로 다룹니다.

### 2.2 `청구서.xlsx`

- 시트: `청구서`, `청구서 BackUp`, `청구서(sample)`
- 실제 양식으로 사용할 시트: `청구서`
- 기본 양식 범위: `A1:I41`
- 상세 제목 행: 19행
- 기본 상세 입력 행: 20행부터 35행까지 16줄
- 합계 행: 36행과 37행
- 상세 금액 수식: H열의 `수량 × 단가`
- 과세대상액 수식: 상세 금액 합계
- 세액 수식: 과세대상액의 10%를 정수로 계산
- 상단 이번달 매출액, 부가세, 이번달 청구액도 하단 합계 수식을 참조함

`청구서(sample)` 시트에는 상세행이 31줄까지 늘어난 예시가 있습니다. 따라서 매출 건수가 기본 16건을 넘으면 합계행과 하단 안내문을 아래로 밀고, 상세행의 병합, 테두리, 글꼴, 표시 형식과 수식을 복사하는 방식으로 확장할 수 있습니다.

청구서 입력 위치는 다음과 같이 사용합니다.

| 입력 내용 | 셀 또는 범위 |
|---|---|
| 거래처 우편번호 | `B5:G5`의 왼쪽 위 셀 `B5` |
| 거래처 주소 | `B6:G6`의 왼쪽 위 셀 `B6` |
| 거래처명 | `B7:G7`의 왼쪽 위 셀 `B7` |
| 매출일 | 상세행 A열 |
| 상품명 | 상세행 `B:E` 병합 영역의 왼쪽 위 셀 B열 |
| 수량 | 상세행 F열 |
| 단가 | 상세행 G열 |
| 금액 | 상세행 H열 수식 |

## 3. 사용 기술

- Python: 전체 처리 순서와 오류 처리
- `openpyxl`: 두 엑셀 파일 읽기, 청구서 작업용 파일 작성, 양식과 수식 유지
- `pywin32`의 `win32com.client`: Microsoft Excel에서 수식 재계산 후 PDF 내보내기
- Python 기본 모듈
  - `pathlib`: 프로그램 위치 기준 경로 처리
  - `calendar`: 지정 월의 마지막 날짜 계산
  - `datetime`: 날짜 범위 검사
  - `tempfile`: 작업용 임시 엑셀 파일 관리
  - `re`: PDF 파일명에 사용할 수 없는 문자 치환

현재 작업 환경에는 `openpyxl`, `win32com`과 Microsoft Excel이 설치되어 있습니다. 실제 프로그램 작성 단계에서는 새 패키지를 설치하지 않고 먼저 현재 환경으로 시험합니다.

PDF 변환은 Microsoft Excel의 PDF 내보내기 기능을 사용합니다. `openpyxl`만으로는 엑셀 수식을 계산하거나 PDF로 저장할 수 없기 때문입니다.

## 4. 실행 방법 설계

프로그램 파일 이름은 `make_invoices.py`로 정합니다.

```powershell
cd C:\myenv_vibe\03-sales
C:\myenv_vibe\.venv\Scripts\python.exe make_invoices.py 2026 10
```

연도와 월을 생략하면 기본값으로 2026년 10월 청구서를 만듭니다.

```powershell
C:\myenv_vibe\.venv\Scripts\python.exe make_invoices.py
```

- 첫 번째 값: 연도
- 두 번째 값: 월
- 연도와 월을 모두 입력하지 않으면 기본값 `2026 10`을 사용합니다.
- 월은 1부터 12까지만 허용합니다.
- 실행 위치와 관계없이 프로그램 파일이 있는 `03-sales` 폴더를 기준으로 파일을 찾습니다.

## 5. PDF 파일 이름과 저장 기준

파일 이름 형식은 다음과 같이 정합니다.

```text
YYYY-MM_청구서_거래처코드_거래처명.pdf
```

예시:

```text
2026-10_청구서_1001_강남상사.pdf
2026-10_청구서_3002_유성식당.pdf
```

- `PDF` 폴더가 없으면 모든 사전검사를 통과한 뒤 생성합니다.
- 같은 이름의 PDF가 있으면 새 PDF로 덮어씁니다.
- 거래처명에 Windows 파일명 금지 문자(`\ / : * ? " < > |`)가 있으면 `_`로 바꿉니다.
- 해당 월에 매출이 있는 거래처만 PDF를 만듭니다.
- 재실행 전에 존재하던 다른 거래처의 같은 달 PDF는 자동 삭제하지 않습니다. 매출이 삭제된 거래처의 예전 PDF가 남을 수 있으므로, 실행 결과에 이번에 생성한 파일 목록과 기존 잔여 가능성을 알립니다.

## 6. 전체 처리 순서

### 1단계: 입력값과 파일 확인

1. 연도와 월이 정수인지 확인합니다.
2. 월이 1부터 12인지 확인합니다.
3. `매출.xlsx`와 `청구서.xlsx`가 존재하고 읽을 수 있는지 확인합니다.
4. Excel에서 파일을 열어 둔 상태여도 읽기는 가능할 수 있지만, 잠금이나 저장 충돌 위험이 있으므로 실행 전에 두 파일을 닫도록 안내합니다.

### 2단계: 엑셀 구조 사전검사

이 단계에서는 원본과 PDF 폴더를 변경하지 않습니다.

1. `매출.xlsx`에 `매출`, `거래처` 시트가 있는지 확인합니다.
2. 필요한 열 제목이 정확히 있는지 확인합니다.
3. `청구서.xlsx`에 `청구서` 시트가 있는지 확인합니다.
4. 거래처 입력 셀, 상세 제목 행, 상세 시작 행과 합계 수식이 예상 위치에 있는지 확인합니다.
5. 양식 구조가 바뀌었으면 잘못된 PDF를 만들지 않고 중단합니다.

### 3단계: 거래처 정보 검사

1. `거래처` 시트를 거래처코드 기준으로 읽습니다.
2. 거래처코드가 비어 있거나 중복되면 중단합니다.
3. 거래처명, 우편번호, 주소가 비어 있으면 해당 거래처와 누락 항목을 알리고 중단합니다.
4. 우편번호는 숫자로 계산하지 않고 문자열로 읽어 앞자리 0을 유지합니다.

### 4단계: 지정 월 매출 추출

1. 시작일을 해당 월 1일 00:00:00으로 정합니다.
2. 종료 경계는 다음 달 1일 00:00:00으로 정합니다.
3. `시작일 <= 매출일 < 다음 달 1일` 조건으로 필터링합니다.
4. 월말 날짜가 28일, 29일, 30일, 31일인 경우를 모두 같은 방식으로 처리합니다.
5. 날짜가 비어 있거나 엑셀 날짜로 해석되지 않으면 행 번호와 함께 오류를 알립니다.
6. 선택한 월의 매출이 한 건도 없으면 PDF를 만들지 않고 종료합니다.

### 5단계: 매출 데이터 검증과 거래처별 묶기

1. 거래처코드, 상품명, 매출수량, 단가가 비어 있지 않은지 확인합니다.
2. 수량과 단가가 숫자인지 확인합니다.
3. 거래처코드가 `거래처` 시트에 없으면 중단합니다.
4. `매출` 시트의 거래처명과 `거래처` 시트의 거래처명이 다르면 중단합니다.
5. `매출수량 × 단가`와 `매출금액`이 다른지 검산합니다. 다른 경우 행 번호와 두 금액을 표시하고 중단합니다.
6. 거래처코드별로 묶고, 각 거래처 안에서는 매출일 오름차순, 같은 날짜에서는 원본 행 순서로 정렬합니다.

### 6단계: 거래처별 청구서 작업 파일 만들기

각 거래처에 대해 다음 순서를 반복합니다.

1. `청구서.xlsx`를 임시 작업 파일로 복사해 원본을 보호합니다.
2. `청구서` 시트에 거래처 우편번호, 주소, 거래처명을 입력합니다.
3. 기본 상세행 20행부터 날짜, 상품명, 수량, 단가를 입력합니다.
4. 상품명은 병합 영역의 왼쪽 위 셀에 입력합니다.
5. 상세행이 16건을 넘으면 부족한 행 수만큼 합계행 바로 위에 행을 삽입합니다.
6. 삽입한 각 행에 기존 상세행의 병합, 높이, 테두리, 글꼴, 채우기, 정렬, 표시 형식을 복사합니다.
7. 각 상세행 H열에 `=F행*G행` 수식을 넣습니다.
8. 합계행 수식을 실제 상세 시작행부터 마지막 상세행까지로 다시 설정합니다.
9. 상단의 이번달 매출액, 부가세, 이번달 청구액 수식이 이동한 하단 합계행을 참조하는지 확인합니다.
10. 사용하지 않는 기본 상세행은 값만 비우고 양식은 유지합니다.
11. 날짜는 실제 날짜 값으로 넣고 양식의 날짜 표시 형식을 유지합니다.
12. 수량과 단가는 숫자로 넣고 금액 수식은 양식에 맡깁니다.

### 7단계: Excel 재계산과 PDF 저장

1. Microsoft Excel을 화면에 보이지 않게 실행합니다.
2. 임시 작업 파일을 엽니다.
3. 수식을 전체 재계산합니다.
4. 청구서 시트의 인쇄 영역을 실제 마지막 안내문 행까지 설정합니다.
5. 세로 방향과 한 페이지 너비 맞춤을 적용합니다. 상세행이 많으면 여러 페이지로 넘어갈 수 있으며 19행의 제목 행을 각 페이지에 반복합니다.
6. PDF를 먼저 임시 이름으로 내보냅니다.
7. PDF 파일이 생성되었고 크기가 0보다 큰지 확인합니다.
8. 검사가 끝난 PDF를 최종 파일명으로 교체합니다. 기존 최종 파일이 있으면 이 시점에 덮어씁니다.
9. Excel 통합 문서를 저장하지 않고 닫고, 임시 엑셀 파일을 정리합니다.

PDF 하나가 실패하면 즉시 중단하고 실패한 거래처를 알립니다. 이미 정상 생성된 다른 거래처 PDF는 유지합니다.

### 8단계: 실행 결과 출력

성공 시 다음 내용을 한국어로 표시합니다.

- 대상 연월
- 읽은 전체 매출 건수
- 해당 월 매출 건수
- 청구서를 만든 거래처 수
- 생성한 PDF 파일 수
- 거래처별 상세 건수와 청구 금액
- 저장한 PDF 경로 목록

## 7. 원본 보호와 오류 처리 기준

| 오류 상황 | 처리 방법 | 원본 엑셀 변경 | PDF 생성 |
|---|---|---:|---:|
| 연도·월 입력 오류 | 사용법을 표시하고 종료 | 안 함 | 안 함 |
| 입력 엑셀 없음 | 없는 파일 경로를 표시하고 종료 | 안 함 | 안 함 |
| 필수 시트·열 없음 | 누락된 이름을 표시하고 종료 | 안 함 | 안 함 |
| 거래처코드 중복 | 중복 코드를 표시하고 종료 | 안 함 | 안 함 |
| 거래처 정보 누락 | 거래처코드와 누락 항목을 표시하고 종료 | 안 함 | 안 함 |
| 해당 월 매출 없음 | 생성 대상이 없다고 알리고 종료 | 안 함 | 안 함 |
| 날짜·수량·단가 오류 | 엑셀 행 번호와 값을 표시하고 종료 | 안 함 | 안 함 |
| 거래처 마스터 불일치 | 거래처코드와 두 이름을 표시하고 종료 | 안 함 | 안 함 |
| 수량×단가와 매출금액 불일치 | 행 번호와 계산값을 표시하고 종료 | 안 함 | 안 함 |
| Excel 실행·재계산 실패 | 거래처와 오류를 표시하고 종료 | 안 함 | 일부 생성 가능 |
| PDF 내보내기 실패 | 거래처와 저장 경로를 표시하고 종료 | 안 함 | 일부 생성 가능 |

## 8. 검산 방법

### 8.1 데이터 건수 검산

1. 지정 월의 `매출` 시트 데이터 행 수를 셉니다.
2. 거래처별 상세 건수를 모두 더합니다.
3. 두 수가 같은지 비교합니다.
4. 생성한 PDF 수와 해당 월에 매출이 있는 거래처 수가 같은지 비교합니다.

### 8.2 거래처별 금액 검산

각 거래처에서 다음 세 값을 비교합니다.

1. `매출.xlsx`의 `매출금액` 합계
2. Python이 계산한 `매출수량 × 단가` 합계
3. 청구서 하단 과세대상액 수식 결과

세 값이 모두 같아야 합니다. 부가세는 양식의 기존 기준대로 `과세대상액 × 10%`의 소수점 이하를 버린 정수이며, 이번달 청구액은 과세대상액과 부가세의 합으로 확인합니다.

### 8.3 PDF 확인

1. 모든 PDF 파일이 존재하고 크기가 0보다 큰지 확인합니다.
2. 첫 번째 거래처, 상세 건수가 가장 많은 거래처, 마지막 거래처 PDF를 직접 열어 표가 잘리지 않는지 확인합니다.
3. 우편번호, 주소, 거래처명, 날짜, 상품명, 수량, 단가, 금액, 합계가 보이는지 확인합니다.
4. 상세행이 16건을 넘는 시험 데이터를 별도 복사본으로 만들어 행 확장과 여러 페이지 출력을 확인합니다.
5. 같은 연월을 두 번 실행해 같은 파일명이 정상적으로 교체되는지 확인합니다.

## 9. 현재 파일로 확인한 기준값

프로그램 작성 후 다음 값으로 1차 검산할 수 있습니다.

| 대상 월 | 매출 건수 | 매출 거래처 수 | 거래처별 최대 상세 건수 |
|---|---:|---:|---:|
| 2026년 10월 | 38건 | 11곳 | 8건 |
| 2026년 11월 | 37건 | 11곳 | 6건 |

현재 데이터에서는 필수값 누락, 거래처코드 누락, 거래처명 불일치, `매출수량 × 단가`와 `매출금액`의 불일치가 확인되지 않았습니다.
