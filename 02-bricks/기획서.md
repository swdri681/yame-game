# 벽돌 미로 게임 기획서

## 1. 프로젝트 개요

- 프로젝트 이름: 비밀 오락 관리부: 벽돌 미로
- 장르: 미로 수집 아케이드 게임
- 개발 언어: HTML, CSS, JavaScript
- 핵심 목표: 검정색 관리 요원을 움직여 오류가 발생한 미로의 빨간 벽돌 데이터를 모두 회수하고 7개 구역을 정상화한다.
- 디자인 방향: 복고풍 전자오락실, 게임 속 비밀 관리부서, 픽셀 요원, 오류 경보 화면을 조합한다.
- 독창성: 특정 웹툰의 이름·로고·캐릭터·장면은 복제하지 않고, 게임 속 숨은 일꾼이라는 큰 주제만 참고해 새로운 설정과 그림을 사용한다.

## 2. 게임 진행 방식

1. 처음에는 `관리 요원 접속 대기` 안내창을 표시하고 게임을 멈춘다.
2. 스페이스키를 누르면 1구역 점검을 시작한다.
3. 사용자는 방향키로 검정색 관리 요원을 상하좌우로 움직인다.
4. 요원이 빨간 벽돌 데이터 위를 지나가면 데이터를 자동으로 회수한다.
5. 회색 오류 추적자가 미로를 돌아다니며 요원을 방해한다.
6. 미로 안의 업무 지원 아이템을 획득하면 효과가 자동으로 발동한다.
7. 오류 추적자와 부딪히면 보안 등급이 1개 줄고 시작 위치로 돌아간다.
8. 구역 안의 벽돌 데이터를 모두 회수하면 다음 구역으로 이동한다.
9. 총 7개 구역을 정상화하면 최종 임무에 성공한다.

## 3. 승리 및 실패 조건

- 각 구역의 빨간 벽돌 데이터를 모두 회수하면 해당 구역을 완료한다.
- 총 7개 구역을 완료하면 승리한다.
- 오류 추적자와 충돌할 때마다 보안 등급이 1개 줄어든다.
- 보안 등급은 3개로 시작하며 모두 잃으면 임무가 종료된다.
- 승리 또는 실패 화면에서 스페이스키를 누르면 처음부터 다시 시작한다.

## 4. 단계와 난이도

- 총 7개의 서로 다른 미로를 사용한다.
- 1~2구역에는 오류 추적자 1개, 3~4구역에는 2개, 5~7구역에는 3개를 배치한다.
- 구역이 올라갈수록 오류 추적자의 이동 속도가 증가한다.
- 상단의 7개 구역 표시등에서 완료한 구역을 빨간색으로 채운다.

## 5. 조작 방법

| 키 | 기능 |
|---|---|
| 스페이스키 | 임무 시작 및 임무 종료 후 다시 시작 |
| 위쪽 방향키 | 위로 이동 |
| 아래쪽 방향키 | 아래로 이동 |
| 왼쪽 방향키 | 왼쪽으로 이동 |
| 오른쪽 방향키 | 오른쪽으로 이동 |

- 키를 계속 누르면 해당 방향으로 연속 이동한다.
- 벽돌 데이터는 별도의 키 없이 자동으로 회수한다.
- 방향키와 스페이스키를 눌러도 브라우저 화면이 움직이지 않게 한다.

## 6. 화면 및 디자인

- 기준 화면은 가로 800px, 세로 600px의 4:3 비율이다.
- 작은 화면에서는 비율을 유지하면서 자동으로 축소한다.
- 낡은 업무용 모니터처럼 두꺼운 회색 테두리, 화면 주사선, 모서리 그림자를 사용한다.
- 바깥 배경에는 관리부의 점검표와 경고 줄무늬 느낌을 표현한다.
- 화면 색상은 청록색과 남색을 중심으로 하고 빨간색을 경고·수집 요소에 사용한다.
- 모든 게임 물체를 각진 픽셀 모양으로 만든다.
- 상단 상태판은 비밀 관리부서의 업무 단말기처럼 구성한다.
- 시작·승리·실패 안내창에는 기밀 문서 도장과 오류 경고 느낌을 사용한다.
- 시작 화면은 밝은 픽셀 하늘, 굵은 그림자 제목, 독창적인 요원과 NPC의 단체 실루엣, 큼직한 임무 시작 버튼으로 구성한다.

## 7. 색상과 게임 물체

| 요소 | 확정 사양 |
|---|---|
| 화면 배경 | 옅은 회색 `#EEEDE5` |
| 하늘과 단말기 | 청록색 `#24A9C7`, 남색 `#173B73` |
| 미로 벽 | 진한 빨간색 `#8B1111` |
| 벽돌 데이터 | 밝은 빨간색 `#E03030` |
| 사용자 관리 요원 | 검정색 `#111111`, 흰색 눈 |
| 오류 추적자 | 회색 몸체, 빨간색 눈 |
| 경고 표시 | 빨강·검정 사선 무늬 |

- 외부 이미지 없이 HTML, CSS, JavaScript로 모든 요소를 그린다.
- 특정 작품의 캐릭터 외형, 이름, 표식은 사용하지 않는다.

## 8. 점수 규칙

- 벽돌 데이터 1개 회수: 10점
- 한 구역 정상화: 추가 300점
- 충돌 없이 구역 정상화: 추가 200점
- 점수는 7개 구역에서 계속 누적한다.

## 9. 게임 규칙 세부 사항

- 게임은 일정한 칸으로 나눈 격자 방식으로 움직인다.
- 벽이 있는 칸으로 이동할 수 없다.
- 방향키를 미리 누르면 다음 갈림길에서 해당 방향으로 자연스럽게 회전한다.
- 오류 추적자는 갈 수 있는 길 중 하나를 선택해 자동 이동한다.
- 오류 추적자는 막다른 길에서 반대 방향으로 이동한다.
- 충돌 직후 1.5초 동안 요원을 깜빡이게 하고 보호한다.
- 구역이 바뀌면 요원과 오류 추적자는 시작 위치로 돌아간다.

## 10. 업무 지원 아이템

- 각 구역에는 일반 길 위에 업무 지원 아이템 1개가 배치된다.
- 아이템은 별도의 키를 누르지 않고 지나가면 자동으로 획득하고 사용한다.
- 같은 구역에서는 아이템이 다시 나타나지 않는다.

| 아이템 | 화면 표시 | 효과 |
|---|---|---|
| 긴급 보호막 | `보` | 오류 추적자와의 충돌을 1회 막는다. |
| 정지 명령 | `정` | 모든 오류 추적자를 4초 동안 멈춘다. |
| 회수 자석 | `흡` | 6초 동안 요원 주변 한 칸의 벽돌 데이터를 자동 회수한다. |

- 1구역부터 `보호막 → 정지 명령 → 회수 자석` 순서로 반복 배치한다.
- 아이템을 획득하면 상단 상태판과 화면 알림으로 현재 효과를 알려준다.
- 회수 자석으로 모은 벽돌 데이터도 개당 10점을 받는다.

## 11. NPC 배달 퀘스트

- 각 구역에는 움직이지 않는 관리부 NPC 1명과 배달 물건 1개가 배치된다.
- NPC에게 닿으면 퀘스트를 받고, 물건을 획득한 뒤 같은 NPC에게 돌아오면 자동으로 배달한다.
- 퀘스트는 선택 사항이므로 완료하지 않아도 다음 구역으로 진행할 수 있다.
- 배달 중 오류 추적자와 충돌해도 물건은 잃지 않는다.
- 퀘스트 상태는 `요청 확인 → 물건 운반 중 → 배달 완료` 순서로 상태판에 표시한다.
- 구역별 NPC는 정비 요원, 기록 요원, 통신 요원, 보급 요원 등 독창적인 관리부 직원으로 표현한다.
- 배달 완료 시 250점과 해당 구역의 지원 아이템 효과를 보상으로 받는다.

## 12. 파일 구성

모든 파일은 `02-bricks` 폴더 안에 둔다.

| 파일 | 역할 |
|---|---|
| `brick_game.html` | 상태판, 게임 화면, 안내창 구조 |
| `brick_game.css` | 4:3 화면과 복고풍 비밀 관리부 디자인 |
| `brick_game.js` | 미로, 이동, 수집, 적, 충돌, 단계와 점수 처리 |
| `기획서.md` | 확정된 게임 규칙과 제작 기준 |

- HTML, CSS, JavaScript는 각각 분리한다.
- 외부 라이브러리와 외부 서비스는 사용하지 않는다.

## 13. 구현 범위

### 포함 기능

- 스페이스키로 시작과 다시 시작
- 방향키 상하좌우 이동과 예약 회전
- 서로 다른 7개의 미로 구역
- 벽 충돌 방지와 벽돌 데이터 자동 회수
- 오류 추적자의 자동 이동과 충돌 판정
- 보호막, 정지 명령, 회수 자석 아이템
- 현재 아이템 효과와 남은 시간 표시
- NPC 접촉, 물건 획득, 자동 배달, 퀘스트 보상
- 현재 퀘스트와 운반 상태 표시
- 단계, 점수, 보안 등급, 남은 데이터 표시
- 단계 완료, 최종 성공, 임무 실패 화면
- 4:3 비율을 유지하는 반응형 화면

### 포함하지 않는 기능

- 원작 웹툰의 이름, 로고, 캐릭터, 그림, 대사 또는 장면 복제
- 다른 고전 게임의 캐릭터, 미로, 소리 복제
- 온라인 순위표, 회원 가입, 실제 개인정보 저장
- 모바일 터치 조작, 외부 서버, 이미지, 음악 및 라이브러리

## 15. 확정 사항

- 기존 벽돌 배달 게임을 벽돌 미로 수집 게임으로 변경한다.
- 100px 벽돌과 150px 배달 바는 미로 게임에 맞지 않아 사용하지 않는다.
- 7층 구조는 서로 다른 미로로 이루어진 7개 관리 구역으로 표현한다.
- 전자오락 세계의 비밀 일꾼이라는 분위기만 참고하고 독창적인 이름과 그림을 사용한다.
- 참고 이미지는 색감, 픽셀 질감, 단체 포스터 구도만 참고하며 원본 로고와 캐릭터는 사용하지 않는다.
- 프로그램 제작과 검사는 이 문서의 완료 기준을 따른다.
